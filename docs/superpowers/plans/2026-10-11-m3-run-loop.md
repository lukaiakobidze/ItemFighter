# M3: Run Loop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Luka can play a full run with the current content. The run covers picking a character, 5 missions of 10 encounter picks plus a boss, fights, shops, building the hotbar before each fight, post-fight drops, gold, selling, levelling by duplicates, saving mid-run, and run won/lost screens.

**Architecture:** All run rules live in Core (`ItemFighter.Core/Run/`) as plain, headless-tested C#:

- config
- state
- offers
- inventory
- economy
- save/load

Every random choice uses a fresh `Rng` forked from the run seed plus a stable key (for example `"shop:2:7:0"`). The run therefore needs no RNG state to save, and the same seed gives the same offers. The Game adds screens that call into that state and reuse `FightScreen` for fights. Every number lives in `Data/run.json` so Luka can rebalance.

**Tech Stack:** as M2 (.NET 8, MonoGame DesktopGL, FontStashSharp, xUnit). System.Text.Json for the save file.

**Spec:** `docs/design/2026-10-10-itemfighter-design.md` §2, §3, §8 (run loop, as decided with Luka on 2026-10-11).

## Global Constraints

- Luka's approved defaults (2026-10-11):
  - The backpack holds 12 items, plus the 6 hotbar slots.
  - Selling gives half the buy price.
  - A drop is items or passives, 50/50, and passives are offered only if any exist.
  - Enemy drop items: Squire Zombie: Sword, Archer Skeleton: Ice Bow, Green Snake: Venom Fang, Flaming Rock: Cinder, Grizzly Bear: Tower Shield.
  - Weighting: the character's pool counts ×3, and each owned item sharing a tag with the candidate adds +15%.
  - Getting a duplicate merges it into one item a level higher.
  - A run is 5 missions × 10 encounters + a boss, picking 1 of 3 each time.
- The hotbar starts each fight as the previous fight's hotbar. The first fight of a run starts empty, apart from the character's starting items.
- A drop offers 3 choices.
  - For an item drop, slot 1 is the enemy's drop item and the other 2 are random by rarity and tags.
  - For a passive drop, slot 1 is one of the enemy's passives, if it has any, chosen by rarity and tags. The rest are random passives.
  - The enemy's rarity shifts the rarity of the random choices up.
- Losing any fight ends the run. Running out of time (2 min) is a loss.
- All numbers are data (`run.json`, content JSON), not code.
- Claude's defaults for gaps the spec leaves open. These are rulings, and each is listed in the hand-off to Luka.
  - HP resets to full every fight.
  - Encounter types for now are Fight, Elite and Shop. Events and rest wait for Luka's designs.
  - Bosses are placeholders from existing enemies with bigger HP, listed per mission in `run.json`.
  - Enemy HP grows +25% per mission.
  - Enemy passives can be taken as player passives. An enemy passive is an `EnemyAbility` with no cooldown.
  - When too few passives exist, the empty choice slots are filled with items.
  - Silver Knight starts with Sword and Metal Plating.

## Review Focus

1. **Inventory full when taking an item:** the item must not vanish or overwrite anything. Expect it to be refused with a clear "make room" state while selling still works. Test: `Inventory_Full_RefusesNewItem_ButMergeStillWorks` (Task 3).
2. **Duplicate of a max-level item:** it must never be offered, so nothing is lost. Test: `Offers_ExcludeOwnedMaxLevelItems` (Task 2).
3. **Corrupt, old or content-changed save file:** expect the run to be dropped (or unknown ids removed) with no crash, and the menu to still work. Test: `Save_Corrupt_ReturnsNull`, `Save_UnknownItemIds_AreDropped` (Task 3).
4. **Fight with an empty hotbar:** the Fight button is disabled until at least one item is on the hotbar. Test: `Prep_CanFight_RequiresAnItem` (Task 3, `RunState.CanFight`).
5. **Quitting mid-fight and continuing:** expect the same encounter to restart with the same seed, not to be skipped or counted as won. Test: `Save_MidFight_ResumesSameEncounter` (Task 3).

### Task 2: Offers (weighted picks for encounters, shops and drops)

**Files:**
- Create: `Core/Run/Offers.cs`
- Test: `tests/ItemFighter.Tests/Run/OffersTests.cs`

**Interfaces:**
- Consumes: `RunConfig`, `ContentDatabase`, `Rng`.
- Produces:
  - `record OwnedItem(string ItemId, int Level)`
  - `enum EncounterKind { Fight, Elite, Shop, Boss }`
  - `record Encounter(EncounterKind Kind, string? EnemyId)`
  - `enum DropKind { Items, Passives }`
  - `record DropOffer(DropKind Kind, IReadOnlyList<string> Choices)`, where Choices are ids of items or passives in display order
  - `static class Offers`:
    - `double ItemWeight(SourceDefinition item, IReadOnlyList<int> rarityWeights, string? characterId, IReadOnlyList<OwnedItem> owned, ContentDatabase db)` = `rarityWeights[(int)item.Rarity] × (item.Pools contains characterId ? CharacterPoolMultiplier : 1) × (1 + TagBonusPercent/100 × countOwnedSharingATag)`
    - `IReadOnlyList<string> PickItems(Rng rng, int count, IReadOnlyList<int> rarityWeights, RunView view, IReadOnlySet<string> exclude)`, distinct, without replacement
    - `IReadOnlyList<Encounter> EncounterChoices(Rng rng, RunView view)`, with ChoicesPerPick entries
    - `DropOffer Drop(Rng rng, string enemyId, bool elite, RunView view)`
    - `IReadOnlyList<string> Shop(Rng rng, RunView view)`
  - `record RunView(RunConfig Config, ContentDatabase Db, string? CharacterId, int Mission, IReadOnlyList<OwnedItem> Owned, IReadOnlyList<string> PassiveIds)`. This keeps Offers independent of the mutable RunState.
- Rules:
  - Items you own at max level (`ContentLoader.LevelCount`) are never offered.
  - Passives you already have are never offered.
  - A pool with zero weight is skipped.
  - When fewer candidates exist than requested, fewer are returned.
  - Elite drops use the enemy's rarity +1 tier, capped at Legendary.
  - Drop: roll `ItemDropChancePercent`.
    - Items: `[dropItem if offerable] + PickItems(rest)`.
    - Passives: `[one of the enemy's passive abilities by rarity weight × tag bonus, if any] + random Passive-kind defs`, then filled with items up to 3.
    - If the passive side would hold no passives at all, it becomes an Items drop.

### Task 3: Run state, inventory, economy, save/load

**Files:**
- Create:
  - `Core/Run/RunState.cs`
  - `Core/Run/RunSave.cs`
- Test:
  - `tests/ItemFighter.Tests/Run/RunStateTests.cs`
  - `tests/ItemFighter.Tests/Run/RunSaveTests.cs`

**Interfaces:**
- Consumes: Task 1 and Task 2.
- Produces `sealed class RunState` (JSON-serializable public properties):
  - `ulong Seed`, `string? CharacterId`, `int Mission` (1-based), `int Encounter` (0..EncountersPerMission; == EncountersPerMission means the boss is next), `int Gold`
  - `OwnedItem?[] Hotbar` (length HotbarSize)
  - `List<OwnedItem> Backpack`
  - `List<string> Passives`
  - `RunPhase Phase` — `enum RunPhase { ChoosingEncounter, Preparing, Fighting, Dropping, Shopping, Won, Lost }`
  - `Encounter? Current`
  - `DropOffer? PendingDrop`
  - `List<string>? ShopStock` and `int ShopRerolls`
  - `int FightsWon`
- Methods (each takes `RunView`-building context `(RunConfig, ContentDatabase)` passed in the constructor and kept as `[JsonIgnore]` fields re-attached by `Attach(config, db)`):
  - `static RunState New(ulong seed, string? characterId, RunConfig, ContentDatabase)` gives the starting gold, puts the character's starting items in the hotbar from slot 0, and sets Phase ChoosingEncounter.
  - `IReadOnlyList<Encounter> EncounterChoices()`. Its key is `"enc:{Mission}:{Encounter}"`, and it returns `[Boss]` when Encounter == EncountersPerMission.
  - `Boss(int mission) → Encounter`
  - `void Choose(Encounter e)` moves a Fight, Elite or Boss to Preparing, and a Shop to Shopping with stock from key `"shop:{Mission}:{Encounter}:0"`.
  - `bool CanFight` is true when the hotbar has an item.
  - `BattleSetup StartFight()` sets Phase Fighting. Its seed is `StableHash.Of($"fight:{Seed}:{Mission}:{Encounter}")`. Enemy HP% = `100 + (Mission-1)×EnemyHpPercentPerMission`, × EliteHpPercent/100 for an elite, or the boss's own hpPercent for a boss.
  - `void FinishFight(bool won)`
    - Lost: sets Phase Lost.
    - Won: adds gold (FightGold[Mission-1], elite × EliteGoldPercent/100, or BossGold for a boss) and FightsWon++, then sets PendingDrop from key `"drop:{Mission}:{Encounter}"` and Phase Dropping.
  - `bool TakeDrop(int index)` returns false if there is no room. Merging always has room.
  - `void SkipDrop()`
  - `void Advance()`
    - Encounter++.
    - After the boss, Mission++ and Encounter = 0.
    - After the last boss, Phase Won. Otherwise Phase ChoosingEncounter.
  - `int Price(string itemId, int level = 1)` = `Prices[rarity] × level`. `int SellValue(OwnedItem)` = `Price × SellPercent / 100` (floored).
  - `bool Buy(int stockIndex)` checks gold and room, then removes the item from stock.
  - `bool Reroll()` costs `RerollBaseCost + ShopRerolls × RerollCostStep` and uses key `"shop:{M}:{E}:{rerolls}"`.
  - `void LeaveShop()` leads to Advance.
  - `ItemRef` is `record ItemRef(bool InHotbar, int Index)`.
    - `void Sell(ItemRef where)`
    - `void Move(ItemRef from, ItemRef to)`: swap. Moving into the backpack's end appends. It refuses if the backpack is full.
  - `bool AddItem(string id)`
    - It merges into an owned copy below max level (level+1).
    - Otherwise it goes to the backpack, or to the first empty hotbar slot if the backpack is full.
    - It returns false when there is no room.
  - `bool HasRoom`
  - `IReadOnlyList<OwnedItem> AllOwned`
  - `RunView View`
- `static class RunSave`:
  - `string ToJson(RunState)`
  - `RunState? FromJson(string json, RunConfig, ContentDatabase)`. It returns null on bad JSON. It drops unknown item and passive ids, clamps levels, and turns a saved Phase Fighting back into Preparing, so a restart replays the same encounter and seed.
  - `Save(string path, RunState)`, `RunState? Load(string path, …)`, `Delete(string path)`, and `Path => Paths.Saves/run.json`. The path is passed in from Game.
